# 插件 × 宿主 兼容性矩阵 · `<YYYY-MM>`（模板）

> 使用方式：每出一版宿主（或每收一版插件），对**每个格子**跑一次静态门禁 + 启动冒烟，把结果填进表格。测试负责人维护，定期（建议随宿主版本节奏）发给团队。
> **这是这套基建的周期性价值载体**：任何一次宿主升级前，本表回答"这次升级谁会碎、要先合什么"。

## 怎么读

| 标记 | 含义 |
|---|---|
| 🟢 | 可用（门禁 0 error，冒烟全过） |
| 🟡 | 带伤可用（0 error 但有 warn，发布前须清零） |
| 🔴 | 不可用（宿主会禁用 / 加载失败 / 冒烟失败） |
| ⚪ | 未测 |

格内格式：`标记 error/warn`，并在括号里给 **1 个决定性错误码**（如 `🔴 3/2（C060 belowMin ×3）`）。

## 单格复现

```bash
# 静态门禁（把 packages 指向插件，hostNodeModules 指向对应宿主安装目录）
node packages/conformance/src/run-all.mjs --config <该宿主×该插件的配置>.json

# 启动冒烟（隔离 home；要点见团队指南 §二/§四）
#   通过判据：无 disabling / 无 pending / 无 failed to import，
#   MISSING_CREDENTIAL 出现在模型调用处，--json 正常退出

# 宿主 API 基线（每宿主一份，供矩阵 diff）
node packages/conformance/src/cli-api.mjs --host <安装目录>/node_modules \
  --baseline api-baseline.<宿主版本>.json --write
```

## 维护约定

- 每格结论必须来自**当次实测**，不允许沿用上期结果（宿主/插件任一变化即重跑）。
- 🔴 格必须链接：体检卡（每插件一份）或修复清单。
- 参照行（宿主自带/市场插件）的发现交给相应维护方，不计入团队指标。
